# 研究与日报

## 时间与筛选

Read the clock, state the cutoff and timezone, and prioritize the previous 24 hours. For the first issue, optionally add important older context under a clearly labeled background section; never silently broaden the time window. Report source-local dates as supplied; only convert a timestamp when its timezone is known. Do not infer release dates from crawl times. Search publication and original event dates separately. Merge coverage of the same event and remove previously covered items when known; do not write a local news log without permission.

Search globally with varied English/Chinese queries, adding regional languages when useful. Cover direct game technology (engines, NPCs, agents, testing, world models, AI-native play), transferable production technology (image, video, 3D, animation, audio, coding, localization, moderation), and major general AI developments. Rank game relevance, demonstrated usability, business impact and source confidence. Do not force a vendor quota, headline count or breakthrough claim.

## Sources

Prefer developer release notes, company announcements, product/API documentation, official code/model repositories, papers and original datasets. Relevant starting points include game engine/platform developer blogs, NVIDIA developer news, Roblox Creator Hub, Microsoft AI, DeepMind, Anthropic, OpenAI, Tencent Hunyuan, Alibaba Qwen, ByteDance Seed, Kling, and original papers. This is a starting list, not an allowlist or a reason to skip other regions. Open the source, verify versions and access conditions; use independent tests and reporting to qualify vendor claims. Social posts and media summaries are leads until verified. Include precise source links near supported claims.

For costs, state preview/promotion conditions and excluded expenses. For demos, check whether users can actually obtain the model, API, SDK or code. A paper or controlled demo is not production availability. If primary sources disagree, preserve the disagreement instead of inventing certainty.

## Output

Chinese by default, about 5–10 minutes reading. Include cutoff/time window and a short reading priority. Give each item an unambiguous report-specific ID such as 20261118-A02. Usually 2–4 detailed game items and 3–6 brief general items, but quality determines count.

Detailed game item: event/version and dates; verified facts plus links; what changed; game roles and concrete uses (label inferences); availability; material limits/costs/commercial conditions if established; a small suggested validation; recommendation (值得试用 / 建议跟踪 / 了解即可); proposed topic and tags. Check relevant production constraints: asset consistency, mesh/topology/rigging, export/integration, latency, deterministic game state, concurrency and language quality as appropriate. Say unknown where sources do not establish something. Do not provide legal conclusions from a marketing page.

General items: short facts/source/status plus why it may affect a game team. End with 1–2 actionable experiments, and an archive invitation such as “归档 20261118-A02、A03，并附上备注……”. Do not archive as part of report generation. Persistent artifacts require the user's explicit selection. If later selection names an ambiguous issue/item, resolve it before writing.
